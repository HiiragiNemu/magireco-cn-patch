# 公开资源迁移准备与私有化门槛

资源同步入口是 `.github/workflows/mirror-public-resources.yml`：主线配置变化、已知发布工作流完成、每小时以及手动触发，统一调用独立公开资源仓中按提交 SHA 固定的实现。它不构建新的 APK，也不提升当前客户端版本。

## 两层兼容

- 资源：客户端下载的 16 个 ZIP、APK 与版本/校验旁注按白名单复制，不整仓发布，不复制草稿和内部审计文件。已传输附件须校验大小与 SHA-256，热更数据同时核对 MD5；版本与配置最后发布。
- 入口：`distribution/personal/_worker.js` 保留原域名、路径与旧源优先级，在旧公开源失败、返回 404 或忽略 Range 时回退独立公开源；只透传白名单路径，不携带用户授权头，保留 HEAD/206/304/416。

公开源通过来源仓库的工作流令牌读取已批准产物，再使用目标写凭证发布；源仓私有化不要求玩家登录，也不把任何凭证写入 APK 或公开配置。

## 本提交不代表已经完成的事项

提交 Worker 源码不等于 Cloudflare 已部署；当前交付检查工作流只核验入口，并非部署工具。需要在原入口部署此兼容版本，再从匿名环境确认 `/health.json` 的 fallbackAuthority 和旧源不可访问时的真实回退。

现有 193 及以下安装包不会因源码变化自动拥有新内置源。需保留原 Cloudflare 兼容入口，并在新 APK 中加入独立公开入口。规范资源 URL、安装完成标记、ZIP 文件名及解压路径保持不变，避免仅迁移下载域名就触发全量重装。

只在同步报告成功、全部资源匿名可读、原入口兼容部署和新 APK 阻断旧仓访问的验收均通过后，才更改源仓可见性。EdgeOne/ESA 暂不改动；仍需冷缓存回源测试，不能把缓存命中当作已经独立。

字体替换、音乐符号检查和 194/195 的正式构建须独立放行；此镜像迁移不声明已消除 193 包内的旧字体。
