# 资源包共同发布与最终覆盖验证

## 当前问题与更正范围

2026-10-02 实际包审计发现：源仓 latest 的 Scenario 3300 落后于公开仓 3322，既有同步因此正确拒绝倒退。两仓 JS 103 和累计补充 21 的 ZIP 字节相同，显示的上传日期不同不代表内容不同。

补充 21 含 128 份剧情：124 份是尚未合入完整剧情包的早期有效修订；另外 4 份会重新覆盖完整剧情包中的后续修订。设备 3 的版本标记为 Scenario 3322 / JS 103 / delta 21，但这四份已安装文件的 SHA-256 均与旧补充包相同。涉及一处 voiceFull、一处 flash/shake 和两处既有角色 ID 迁移。

只检查包版本、只比较 APK 或在发布客户端时确认资源未变，都不足以证明最终剧情正确。完整剧情更新后还会重放已缓存补充包，因此不能直接删除 supplemental_product_paths 或只改安装顺序。

## 唯一生产流程

源码、已有翻译和剧情修订仍以本仓 main 为准。不改 Reader 或网页播放器。累计贡献和完整已处理/待处理台账仍只在本仓维护。

使用 Actions 中的“统一资源包发布”（路径仍为 `.github/workflows/publish-js-delta.yml`）。它同时生成完整 Scenario 和累计 JS delta，写入两个仓库已有的 `latest`。不再为每个剧情批次创建新的公开 Release 或新的编号发布工作流。剧情校订流程完成 main 同步后，应执行或等待此统一工作流，并核对其实际发布报告；不能只单独推公开仓的 Scenario。

构建程序 `tools/build_coherent_resources.py` 从同一个固定 Git 提交取内容。完整剧情的每一份文件必须与该提交的 Git blob 一致；之前的补充包只能作为经过源 blob 核对的字节缓存，不能取代源码权威。原有完整 JS 基线保持不变。只有实际内容变化才提高对应版本，无变化时保留原 ZIP 和版本。

同一条剧情路径若仍被完整 JS 或累计 delta 携带，其最终字节必须与完整 Scenario 一致。`tools/resource_layers.py` 逐个核对实际 ZIP；发布后的完整 Scenario 清单带 ZIP SHA-256 及逐文件 SHA-256，供同步任务低开销检查。不得删除版本单调性或交叠一致性检查来让任务变绿。

## 发布事务

`tools/publish_coherent_resources.py` 默认只准备，显式 `--publish` 才对外修改。它保存两边的发行前身份和受影响文件，以较新的实际剧情包作为可核对缓存，从 main 构建，更新分块清单，并逐包验证普通匿名 URL 的完整字节。只替换 Scenario、delta 及其五份相关元数据，共七个既有附件；APK、完整 JS、基础包、语音和图像/影片独立包不由它改动。

ZIP 和配套清单先于版本门槛，累计 delta 的新版本先于新 Scenario 版本。每次写入前重查全部附件身份；并行发布者改变现场就停止，重新核对，而不是覆盖。新版本尚未可见时可以恢复受影响的原件；任何新版本已经公开后必须前向修复，不能倒退版本号或把旧包重新冒充新包。

统一资源工作流、公开仓同步、客户端发布共用源仓的 `public-player-resource-mirror` 串行组。公开仓历史编号工作流不再承担日常生产发布。旧回退产物不能混入玩家默认 Release 列表；归档处理须保留回退和确认在用 URL 不依赖历史标签。

## 验证

- `python tools/test_resource_layers.py -v`：旧最后覆盖层反例、来源合并、错误基线、未声明文件。
- `python tools/test_coherent_publication.py -v`：发布顺序、并发拒绝、版本倒退拒绝、无变化、失败恢复和版本门槛已公开时不倒退。
- 原有累计补充、公开镜像和仅客户端发布测试继续保留。
- `tools/StoryResourceLayerInstallTest.java` 可链接原客户端编译类，在全新隔离目录中执行实际 `CNHotUpdateTx` / `CNJsDelta`，复现四个旧回写，并验证修复后的完整安装及重装后缓存重放。它不是 APK 代码，也不更换任何用户字库。
- `tools/audit_installed_resource_layers.py` 仅在明确指定、已有读取权限的 ADB 设备上读取资源 SHA-256；不会打开 root、清数据、重装或修改设备文件。必须在更新结束后再审计。

玩家入口固定为公开仓 `releases/tag/latest`，自动下载保持 `releases/download/latest/<原文件名>`。不要要求玩家寻找编号迭代 Release。上传时间不是完成证明，以普通下载 URL、配套清单、最终安装内容的一致性为准。

## 完整清单的传输限额

逐文件 SHA-256 使完整 Scenario 清单超过旧的 2 MiB JSON 上限。下载代理仅对 `cn_scenario_update_manifest.json` 使用 4 MiB 流式读取上限；在线配置、版本和其他清单维持原限额。上限判据在读取过程中执行，超限会取消响应。对应真实生产 502 的反例已并入原 Worker 测试，不降低 ZIP/版本/摘要检查，也不改客户端、正文或资源字节。
